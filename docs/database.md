# Database

PostgreSQL via Prisma 7 (driver-adapter mode, `@prisma/adapter-pg`). Schema:
`apps/backend/prisma/schema.prisma`. Migrations: `apps/backend/prisma/migrations`
(generated by `prisma migrate dev`).

## Models

| Model                 | Purpose                                          |
| --------------------- | ------------------------------------------------ |
| `User`                | Accounts, role (USER/ADMIN), status              |
| `Session`             | Refresh-token sessions (hashed tokens, expiry)   |
| `Meeting`             | Meeting metadata + lifecycle status              |
| `TranscriptSegment`   | Text segments; `clientSegmentId` unique per meeting (sync idempotency) |
| `MeetingSummary`      | Structured notes (summary + JSON sections)       |
| `ActionItem`          | Tasks extracted from meetings                    |
| `SpeakerMapping`      | "Speaker 1" → real name mapping                  |
| `Template`            | System + custom templates (JSON schema)          |
| `Setting`             | Per-user key/value settings                      |
| `AuditLog`            | Admin/security event log                         |

## Key constraints

- `User.email` unique; `Session.tokenHash` unique.
- `TranscriptSegment @@unique([meetingId, clientSegmentId])` prevents duplicate
  syncs of the same segment.
- Cascades: deleting a `User` deletes their meetings, segments, summaries,
  action items, templates, sessions. Deleting a `Meeting` cascades to its
  segments/summaries/action items. Deleting a `Template` sets `Meeting.templateId`
  to null (SetNull).
- There are **no audio columns** and **no audio tables**.

## Indexes

- `User[@role]`, `Session[@userId, @expiresAt]`
- `Meeting[@userId, createdAt]`, `[@userId, status]`, `[@userId, startedAt]`
- `TranscriptSegment[@meetingId, startTime]`
- `ActionItem[@userId, status]`, `[@meetingId, status]`, `[@sourceSegmentId]`
- `Template[@userId, isDefault]`, `[@type]`
- `AuditLog[@createdAt]`, `[@userId, createdAt]`, `[@action]`
- `TranscriptSegment.searchVector` (PostgreSQL `tsvector`), maintained by DB
  triggers: incremental weight-B concat on segment INSERT (the hot sync path)
  and full recompute on the rare UPDATE/DELETE (see migration
  `2026_09_30_incremental_search_trigger`). Backend meeting search
  (`GET /api/meetings?q=…`) queries this index.

## Local / embedded development

Without Docker, `npm run db:up` runs a real PostgreSQL 18 instance from the
`embedded-postgres` package into `./data/pg` (git-ignored). `npm run db:down`
stops it. The `DATABASE_URL` points at `127.0.0.1:55432` by default.

## Migrations workflow

```sh
npm run db:generate   # generate client after schema changes
npm run db:migrate    # create + apply migrations (dev: prisma migrate dev)
npm run db:seed       # seed admin@callnotes.local + demo@callnotes.local
```

Migrations are applied with `prisma migrate deploy` in the `npm run verify`
end-to-end harness and in production deployments.
